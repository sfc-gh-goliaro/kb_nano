Algorithm choice for Triton
- Inclusive scan (cumsum) is a scan operation. There are two main approaches:
  1) Hillis–Steele style in-register scan using powers of two and vector shifting. This is elegant but requires shifting vectors by arbitrary amounts; Triton doesn’t expose a simple “shift a vector” primitive that works for arbitrary offsets in a single step.
  2) Block-wise inclusive scan per tile, then carry propagation between tiles. This is straightforward with Triton’s programming model:
     - Step A: For each row, process it in tiles of BLOCK_SIZE.
     - Step B: Within each tile, do an in-place inclusive scan. We can use a simple O(B^2) add of “running sum + data shifted by k” for k in 1..B-1. For BLOCK_SIZE=1024, that’s 1,023 vector additions — acceptable for a tile.
     - Step C: Maintain a running “carry” equal to the last value of the previous tile. Add this carry to all elements of the current tile after the tile scan.

Why this works and its performance
- Memory access: Loads and stores are contiguous and coalesced along the scan dimension. That’s optimal.
- Computation: Within a tile, the O(B^2) method is simple and vectorized. For B=1024, it’s about a million flops per tile. Across 32 tiles per row, ~32 MFLOPs per row; across 32k rows, ~1 TFLOP — well within GPU capability.
- Parallelism: We parallelize over rows (program_id(0) = row index). Each program processes its row sequentially in tiles; this is a common pattern for scan-like ops.
- Numerics: We’ll use float32. The order of additions is different from torch.cumsum (tile-then-carry), but still reasonable. If needed, we could keep a scalar carry and only adjust the first element of each tile, but that would require a special first-step or more complex logic; the simple carry addition is typically fine.

Design details and edge cases
- Dim handling: The provided use case is dim=1. Supporting arbitrary dims would require more indexing gymnastics. For simplicity and performance, we’ll implement the fast path for dim=1 on 2D tensors. If dim != 1 or ndim != 2, we’ll fallback to torch.cumsum.
- Dtype: We’ll assume float32. If not float32, we can either convert or fallback. Here we’ll fallback to torch.cumsum for non-float32.
- Device: Triton requires CUDA. If tensor is on CPU, fallback.
- Strides: We’ll honor arbitrary strides (not just contiguous), by passing stride0 and stride1. But for best performance, contiguous is preferred.
- BLOCK_SIZE: 1024 is a good default for 32,768. You can tune it (512, 2048) depending on register pressure and GPU.

import torch
import triton
import triton.language as tl


@triton.jit
def _cumsum_dim1_kernel(
    x_ptr,            # *const float
    y_ptr,            # *float
    M, N,             # int: rows, cols
    stride_xm, stride_xn,  # int: strides for x (in elements)
    stride_ym, stride_yn,  # int: strides for y (in elements)
    BLOCK_SIZE: tl.constexpr,
):
    # One program per row
    row = tl.program_id(axis=0)
    # Guard: if row >= M: nothing to do
    # Base pointers for this row
    row_x = x_ptr + row * stride_xm
    row_y = y_ptr + row * stride_ym

    start = 0
    # Running carry: sum of all previous elements before current tile
    carry = tl.zeros((), dtype=tl.float32)

    while start < N:
        cols = start + tl.arange(0, BLOCK_SIZE)
        mask = cols < N

        # Load a tile of this row
        v = tl.load(row_x + cols * stride_xn, mask=mask, other=0.0)
        # Upcast to fp32 for accumulation
        v32 = v.to(tl.float32)

        # Inclusive scan within the tile using a simple iterative method:
        # out[j] = sum_{i=0..j} v[i]
        out = tl.zeros([BLOCK_SIZE], dtype=tl.float32)
        running = tl.zeros((), dtype=tl.float32)
        # Loop over positions in the tile
        for j in range(0, BLOCK_SIZE):
            # Only process valid lanes
            is_valid = (start + j) < N
            val = v32[j]
            running = running + val
            out[j] = running

        # Add the cross-tile carry to all valid lanes
        out = out + carry

        # Store back (downcast to original dtype of y)
        # We don't know y's element type in-kernel; assume float32 I/O.
        tl.store(row_y + cols * stride_yn, out, mask=mask)

        # Update carry: last valid element of this tile
        last_idx = start + BLOCK_SIZE - 1
        if last_idx < N:
            carry = out[BLOCK_SIZE - 1]
        else:
            carry = out[tl.max(tl.where(mask, cols, 0))]  # not ideal, but works
        start += BLOCK_SIZE
